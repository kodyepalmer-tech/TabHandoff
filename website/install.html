Setup & troubleshoot

Primary path: desktop + local AI → browser task → real result → saved history. ZIP export is optional. This page never invents a live store or installer URL.

Not live yet: Chrome Web Store listing · signed macOS/Windows installers · production tabhandoff.com DNS. Until those ship, use the paths below.

1. Desktop + local AI (primary)

The desktop app hosts the local bridge, shows activity / AI task history, and keeps results under ~/.tabhandoff/.

Run from source (works today on every OS)

  1. Install Node.js 22+ and enable Corepack (corepack enable).
  2. Clone and build: 
    git clone https://github.com/kodyepalmer-tech/TabHandoff.git
cd TabHandoff
pnpm install && pnpm build
pnpm desktop
  3. Optional free local model: install Ollama, pull a small model, leave the Ollama app running.
  4. Copy the access token the desktop/bridge shows (needed for the browser extension to talk to this computer).

Packaged installers appear on Download only when a GitHub Release asset exists. Early builds are unsigned — expect Gatekeeper / SmartScreen prompts until the founder adds signing.

macOS installer (when published)

  1. Download the .dmg for your chip from GitHub Releases.
  2. Open the disk image and drag TabHandoff to Applications.
  3. First launch: if Gatekeeper blocks an unsigned app, open System Settings → Privacy & Security → Open Anyway, or right-click → Open.

Windows installer (when published)

  1. Download the NSIS .exe (x64) from GitHub Releases.
  2. Run the installer.
  3. If SmartScreen appears: More info → Run anyway only for the official GitHub Release asset.

Linux installer (when published)

chmod +x TabHandoff-*-linux-*.AppImage
./TabHandoff-*-linux-*.AppImage
# or: sudo apt install ./TabHandoff-*-linux-amd64.deb

2. Browser extension (Load unpacked until CWS)

Chrome Web Store is not live. There is no public CWS listing. Use Load unpacked — this is the developer / early-tester path until the founder publishes to the store.

  1. Open Chrome, Edge, or Brave → chrome://extensions.
  2. Turn Developer mode on.
  3. Load unpacked → select packages/extension in the cloned repo (or unpack artifacts/tabhandoff-extension-*.zip from pnpm pack:extension).
  4. Pin TabHandoff to the toolbar.
  5. Extension → Settings → paste the desktop/bridge token → Save.

Run a task

  1. Open a normal https://… page (not chrome://).
  2. Right-click → Hand off with TabHandoff (or the toolbar button).
  3. Write what you want done → Review.
  4. Primary: Run with AI (local bridge) — result and history stay on this computer.
  5. Optional: also download a portable ZIP if you want to share context. ZIP is not required for the AI path.

Repo guide: docs/extension-setup.md · Privacy

Optional: ZIP-only (no AI)

You can still Save package / download a ZIP without the desktop app. Status will say the package was created — not that an agent ran. Useful for sharing; not the primary AI path.

Where data lives

  • macOS / Linux: ~/.tabhandoff/
  • Windows: %USERPROFILE%\.tabhandoff\
  • Override: TABHANDOFF_HOME

Troubleshooting (plain language)

  • “Bridge: off” / can’t Run with AI: Start pnpm desktop (or pnpm bridge), copy the token again into extension Settings.
  • Port already in use: Quit the other TabHandoff window, or change the port in ~/.tabhandoff/bridge.json.
  • Local model errors: Confirm Ollama is running and the model name includes its tag (example: smollm2:135m, not just smollm2).
  • Can’t hand off chrome:// pages: Open a normal website instead.
  • No screenshot: Some pages block capture — URL + instruction still hand off.
  • Desktop “Coming soon” on Download: No published installer for that OS yet — use from-source above.
  • More: docs/troubleshooting.md · Support
